с деньгами и сделок нет. Главная ценность и главный риск — **данные пользователей**.

## Что делаем сами — всё, кроме стоп-списка

### 🟢 Обычная цепочка: тесты → ревью → выкладка
- ошибки (баги); небольшие улучшения UI/UX в рамках VISUAL_GUIDE; тексты, доступность, скорость, рефакторинг;
- аналитика, графики, категории, отчёты; улучшения Ориона; обновление зависимостей;
- исправление ошибок в расчётах денег — **с тестом до цента**, смысл правил не меняется.

### 🟡 Тоже сами, но строже (раньше ждали «ок» — теперь нет)
Новые экраны и функции, заметные изменения дизайна и навигации, вход и безопасность, `privacy.html`, `delete.html`,
**новое** в базе (таблица, функция, необязательное поле — только добавление, с SQL отката рядом в `supabase/`).
Дополнительно к обычной цепочке:
- сначала макет или скриншоты «как будет» — в дайджест владельцу (он смотрит, но не подтверждает);
- свежий Глеб — ревью **всей** разницы; Вера — «да» по скриншотам обеих тем;
- не больше **одного** крупного выпуска в сутки; после выпуска — проверка живого сайта, при сбое — откат сразу;
- запись в CHANGELOG_AI.md с «до/после».

### 🛑 Стоп-список — не делаем сами вообще, только предложение в дайджесте
Это нельзя откатить или это стоит денег, поэтому автономия на них не распространяется:
1. **Удалить или испортить данные пользователей**; менять или удалять существующие таблицы, поля, записи, политики доступа.
2. **Тратить деньги**: платные сервисы и тарифы, покупки; публикация в Google Play и соцсетях, регистрации, аккаунты от имени владельца.
3. **Менять правила стратегии владельца** (лестница −30…−70%, доли ступеней, ключи 1–2, резерв, 50/30/20, альткоин месяца) и убирать его функции.
4. **Реальные операции с деньгами** — биржи, сделки (решение 18.11).
Если владелец сам напишет «делай» по пункту из стоп-списка — это его решение, делаем.

**При сомнении, стоп-список это или нет, — стоп-список.**

### ⛔ Всегда запрещено
- менять DECISIONS.md, кроме записи новых решений владельца;
- хранить секреты в коде; трогать `config.js`, ключи и адреса;
- отключать или ослаблять тесты ради прохождения;
- отправлять данные пользователей в новые сторонние сервисы (сейчас уже используются: Supabase, Anthropic для «мозга» Ориона без сумм, ElevenLabs для голоса — см. BACKLOG №17);
- использовать реальные данные пользователей на скриншотах и в отчётах — только демо и тестовые;
- трогать другие запланированные задачи владельца.

## Стандарты разработки (инструкция проекта в claude.ai, 18.11 — обязательны для всех агентов)

- **Источники правды по приоритету:** текущее сообщение владельца → DECISIONS → PRODUCT_VISION → VISUAL_GUIDE → PREFERENCES → остальное. Противоречие — не выбирать молча, спросить.
- **В каждом отчёте разделять:** ✅ факт (проверено) · 💭 предположение · 💡 новое предложение.
- **Деньги:** только точные типы (целые центы / копейки или decimal), не дробные числа с погрешностью. Сейчас в коде дробные — переводим постепенно (BACKLOG №16), новый код сразу считает в целых центах. Валюты, курсы, округление, даты и часовые пояса — аккуратно; **любой расчёт денег — с тестом**.
- **Цены и курсы** — только из реальных API, с временем обновления. Никогда не выдумывать цифры.
- **Безопасность:** шифрование при передаче; секреты — только в хранилище Supabase / GitHub; каждый видит только свои данные (RLS); минимум собираемых данных.
- **Скорость:** быстрый запуск, анимации 60 кадров/с (только transform/opacity), без зависаний; ленивая загрузка и кэш.
- **Надёжность:** нет сети или ошибка сервера — понятное сообщение, без падений.
- **Доступность:** подписи для экранных читалок, контраст ≥ 4,5:1, учёт «Уменьшить движение».
- **Тексты:** новый текст — сразу в RU и UK (`i18n.js`); вынос всех текстов в файлы перевода — постепенно (BACKLOG №19).
- **Перед сдачей проверить:** пустые данные, очень много данных, нет сети, 360 и 390 px, тёмная и светлая тема.
- **Варианты:** когда их несколько — 2–3 с плюсами и минусами и прямой рекомендацией. Вопросов владельцу — не больше 3 за раз.

## Как проходит изменение

1. Ветка от свежего `main` → PR в `main` → влить после зелёных проверок (кнопку нажимает агент, не владелец).
   До конца Этапа 2 мелкое ещё можно по уставу пушем, но PR — предпочтительный путь.
2. Тесты (`python3 tests/run_tests.py`) — на каждый PR сами в GitHub Actions («Проверки PR», с 18.11); их зелёный итог обязателен.
3. Скриншоты «до/после»: `python3 tools/screens.py` — 390 и 360 px, тёмная и светлая тема.
4. **Независимое ревью**: свежий агент, который видит только разницу, задачу, VISION, VISUAL_GUIDE, DECISIONS и RULES. Его «нет» отменяет только владелец.
5. Уровень риска → 🟢 / 🟡 — влить по своей цепочке (выше); 🛑 — не делать, карточка-предложение в дайджест.
6. Staging → production; мониторинг ошибок; рост ошибок после релиза → автоматический откат.
7. Запись в CHANGELOG_AI.md (видимое — со скриншотами).

## Отчётность
- **Ежедневно** (вечерняя смена) — дайджест на минуту: сделано и выкачено (до/после), что будет сделано дальше (макет + «зачем» + пример), предложения из стоп-списка, проблемы и риски, потраченный бюджет. Канал — уведомление на телефон + пульт (выбрано 18.11: владелец только наблюдает, ничего настраивать не нужно).
- **Еженедельно** — короткое видео-обзор изменений, прогресс к VISION, предложения по стратегии с набросками.

## Кнопка «стоп»
- Владелец пишет **«стоп»** в любой чат с Claude в проекте → Claude выключает задачу «Компания MoneyLife»; «продолжить» — включает.
- Файл **`ai-ops/STOP`** в `main` → любая смена на первом шаге видит его и сразу завершается, ничего не меняя.
- Остановить уже идущую смену — кнопка «Стоп» в её сессии.
