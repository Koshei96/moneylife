# MoneyLife в Google Play: упаковка сайта в Android-приложение (TWA)

*Подготовил Илья (ведущий программист), 2026-10-28. Для владельца — простыми словами.*

## Что такое TWA

TWA (Trusted Web Activity — «доверенное окно сайта») — это способ выложить наш сайт
https://koshei96.github.io/moneylife/ в Google Play как обычное приложение. Внутри приложения
открывается тот же сайт через Chrome, но **без адресной строки** — выглядит как настоящее приложение.
Обновлять приложение в магазине почти не придётся: всё, что попадает на сайт, сразу появляется и в приложении.

Собирает такое приложение бесплатная программа **Bubblewrap** или сайт **PWABuilder** (pwabuilder.com) —
им достаточно адреса сайта, остальное они берут из «паспорта» приложения (файл `manifest.webmanifest`).

## Что уже готово (сделала команда)

- **Паспорт приложения** (`manifest.webmanifest`): название, описание, язык — русский, категория
  «Финансы», иконки (обычная и «маскируемая» — для круглых/квадратных значков Android), постоянный
  идентификатор приложения и три быстрых ярлыка: «Монеты», «Стратегия», «Активность»
  (долгое нажатие на значок приложения — сразу нужная вкладка).
- **Заготовка файла-подтверждения** `.well-known/assetlinks.json` (о нём ниже).
- Автотест проверяет, что паспорт правильный и иконки на месте.

## Главная загвоздка: файл-подтверждение должен лежать в «корне» сайта

Чтобы Android убрал адресную строку, он проверяет, что сайт и приложение принадлежат одному владельцу.
Для этого на сайте должен лежать файл-подтверждение по адресу **строго**:

`https://koshei96.github.io/.well-known/assetlinks.json`

А наш сайт живёт «в подпапке»: `https://koshei96.github.io/moneylife/`. Всё, что лежит в репозитории
`moneylife`, попадает только внутрь `/moneylife/…`. Поэтому заготовка в нашем репозитории
(`/moneylife/.well-known/assetlinks.json`) **сама по себе не сработает** — это только образец.

### Варианты

1. **Рекомендую: отдельный маленький репозиторий `koshei96.github.io`** (бесплатно, 5 минут).
   GitHub отдаёт такой репозиторий как «корень» адреса `koshei96.github.io`. В нём будет всего два файла:
   `.well-known/assetlinks.json` (копия нашей заготовки с настоящим отпечатком) и пустой `.nojekyll`.
   Наш сайт `/moneylife/` при этом продолжит работать как раньше.
2. **Свой домен** (например `moneylife.app`) — стоит денег каждый год, нужно настраивать.
   Тогда сайт переезжает в корень домена и файл кладётся прямо к нам. Пока не нужно.
3. **Ничего не делать** — приложение всё равно соберётся и запустится, но сверху будет видна
   адресная строка Chrome. Выглядит несолидно; для первого теста допустимо, для магазина — нет.

## Название пакета (решение владельца)

Каждое Android-приложение имеет уникальное «имя пакета». Предлагаем:
**`io.github.koshei96.moneylife`** — по адресу сайта, так принято.
**Важно:** после первой публикации в Google Play имя пакета изменить нельзя никогда.
Если хотите другое (например, под будущий свой домен) — скажите до сборки.

## Что такое «отпечаток ключа» (SHA-256)

Приложение в магазине подписывается цифровым ключом — как печать. «Отпечаток» — это длинная строка вида
`AB:CD:12:…` (32 пары символов через двоеточие). Его и нужно вписать в файл-подтверждение вместо
заглушки `ЗАМЕНИТЬ:НА:SHA-256:…`. Отпечаток не секретный, его можно публиковать.

Google Play обычно переподписывает приложение своим ключом (Play App Signing), поэтому в файл кладут
**два** отпечатка: ключа загрузки (выдаёт Bubblewrap/PWABuilder при сборке) и ключа Google
(Play Console → ваше приложение → «Проверка целостности приложения» / «Подпись приложения»).

## Пошагово: что понадобится от вас

1. **Аккаунт разработчика Google Play** — разовый взнос 25 $, регистрация на play.google.com/console.
   Регистрируете сами; команда аккаунты не создаёт и пароли не просит.
2. **Подтвердить имя пакета** `io.github.koshei96.moneylife` (или назвать своё) — одним сообщением в чат.
3. **Разрешить создать репозиторий `koshei96.github.io`** (или создать самому: GitHub → «New repository» →
   имя ровно `koshei96.github.io`, публичный). Команда подготовит в нём файлы.
4. **Сборка приложения** — на pwabuilder.com: вставить адрес сайта → «Package for stores» → Android.
   Сайт выдаст архив: файл приложения для магазина (`.aab`), ключ подписи и пароль к нему.
   **Ключ и пароль сохранить в надёжном месте** (без них нельзя выпускать обновления) и никому не
   присылать, в том числе команде — нам нужен только отпечаток (он есть в том же архиве, в файле
   `assetlinks.json`).
5. **Прислать в чат отпечаток(и)** — команда впишет их в файл-подтверждение.
6. **Загрузить `.aab` в Play Console**, заполнить карточку (тексты и картинки готовят Алина и Вера).

## Что ещё осталось сделать команде

- **Скриншоты в паспорте** (`screenshots`) — пока не добавлены: нужны настоящие красивые снимки экранов
  без личных данных (с демо-портфелем). Их же используем для карточки в Google Play.
- После получения отпечатка — заполнить `assetlinks.json` в репозитории `koshei96.github.io` и проверить
  его официальным тестером Google (Statement List Tester).

## Технические заметки для команды

- `id` манифеста = `"/moneylife/"`. Раньше `id` не было, и браузер считал идентификатором `start_url`,
  то есть `https://koshei96.github.io/moneylife/`. Значение `"/moneylife/"` даёт ровно этот же адрес
  (и при разборе от корня сайта, и от `start_url`), поэтому уже установленная у владельца PWA не
  «раздвоится». Вариант `"./"` опасен: по спецификации `id` разбирается от origin, и получилось бы
  `https://koshei96.github.io/` — новый идентификатор, браузер посчитал бы это другим приложением.
- Ярлыки ведут на `./#coins`, `./#strategy`, `./#activity` — `index.html` уже открывает вкладку по
  хэшу при запуске (`startTab`).
- `.nojekyll` в корне репозитория уже есть, поэтому GitHub Pages отдаёт папки с точкой (`.well-known`).
  В репозитории `koshei96.github.io` он тоже обязателен.
- Файл-подтверждение должен отдаваться по HTTPS, без переадресаций, с типом `application/json` —
  GitHub Pages так и делает.
