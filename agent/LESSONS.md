# Уроки команды

Память команды: правила из опыта. Читают все агенты каждую смену. Не больше 40 строк — при разборе недели
сжимать и убирать устаревшее. Формат: `- ГГГГ-ММ-ДД — правило (почему)`.

- 2026-11-13 — Service worker в тест-браузере выключен: логику sw.js проверять запуском обработчика в node с имитацией fetch/caches (так Илья
  поймал 404) и честно писать, что на живом Chrome/TWA не проверено. Полоску жестов Chromium имитирует `Emulation.setSafeAreaInsetsOverride`.
- 2026-11-12 — Сессия Claude с владельцем правит main прямо в смену (свежий коммит < 1 ч) — мелкое не выкладывать, только исследование и учёт: иначе конфликт меток с его работой.
- 2026-11-12 — Две мелкие правки за смену: Илья делает обе одним вызовом в двух ветках с метками по возрастанию; Вера — одним вызовом, Глеб —
  два параллельно (4 вызова). Вторую при перебазировке ждёт конфликт только меток — брать её метку в кусках конфликта и сверять diff.
- 2026-11-10 — Цена монеты с биржи принимается, только если есть с чем сверить (CoinGecko, живые цены или `app/market`): в демо и тестах без этой опоры альткоин остаётся «без цены». Большой выпуск показывать владельцу кусками по 1–3 работы — так он успевает проверить и не сгорает лимит.
- 2026-11-10 — Смена, упёршаяся в лимит, оставляет `meta/agent` в «running» и не пишет учёт: следующая смена сверяет `git log origin/main`
  с LOG.md и дописывает невнесённые выкладки. Пока идёт чужая большая работа (v3-wip) — 1 вызов Agent, только исследование.
- 2026-11-08 — Одобренный выпуск: `gh api …/merges` закрыт прокси (403) — сразу `git push origin <approvedSha>:main` (ff, без force,
  урок 05.11 верен; урок 03.11 про отдельную ветку и Merge владельцем устарел).
- 2026-11-08 — В проверках «часы назад» писать оба состояния: карточка прочитана и не прочитана (Глеб поймал 2 карточки за день).
  Код фишки параллельно со спекой и макетом ускоряет, но правки текстов Веры потом нужен отдельный круг — закладывать его в план.
- 2026-11-07 — Ветка agent ведётся слияниями: `git rebase origin/main` на ней даёт конфликты на старых коммитах — не перебазировать, проверять
  `merge-base --is-ancestor origin/main origin/agent`. Ветку для worktree ревью Глеба давать через `--detach <sha>` (ветка уже выведена).
- 2026-11-07 — Мелкое и крупное в одну смену: выложить мелкое, затем перемотать agent на ветку крупного (ff-only) и влить main;
  в конфликте меток брать только конфликтующие куски agent (не файл целиком) и сверять `git diff <ветка> HEAD` — должна быть ровно правка main.
- 2026-11-06 — Две независимые правки: Илья — параллельно в двух worktree, Вера смотрит обе одним вызовом, Глеб — два параллельных ревью.
  5 вызовов вместо 6 и запас на круг исправлений.
- 2026-11-06 — Жалобу «неверная цифра» сначала сверить с кодом: «BTC $38,39» оказалось суммой докупки, а не ценой — чинить нужно было
  текст. Владельцу говорить правду о причине, даже если накануне в чате предположили другое.
- 2026-11-06 — Правка «заодно» в коммите мелкого (вибрация) — повод для «нет» Глеба. Шум браузера в тесте — в IGNORE_CONSOLE, не в код.
- 2026-11-05 — Одобренный выпуск вливать перемоткой: `git push origin <approvedSha>:main` (без force, только если main — предок sha).
  Merge через API (`gh api …/merges`) проверка автоматики отклоняет; PR с этим sha GitHub сам закрывает как merged.
- 2026-11-05 — Пока одобренный выпуск не влит, мелкую выкладку в `main` делать с оглядкой: она меняет метку версии, и PR выпуска
  начинает конфликтовать. Тогда — слияние main в ветку выпуска (только метка), ревью Глеба, карточка снова `ready` с новым sha.
- 2026-11-04 — Ветку `agent` не перебазировать: `push --force` автоматике запрещён. Вливать `origin/main` в `agent` обычным
  merge; при конфликте меток версии брать файл main ЦЕЛИКОМ нельзя — он съедает правки agent (так потерялась «Одна монета»,
  поймал тест). Сверять `git diff` с прежней веткой: должны отличаться только метки.
- 2026-11-04 — Мелкое в `main` выкладываем `git push origin HEAD:main` — это разрешено; запрещён только merge через API. Сборку сайта
  проверять через GitHub MCP `actions_list` (запуск «pages build and deployment», conclusion success) — `pages/builds` закрыт прокси.
- 2026-11-04 — «Сделать кнопку видимой» — не всегда доступность: если кнопка меняет выбор человека (стратегию), это крупное. Сначала
  смотреть, что делает обработчик и задумывалась ли кнопка в этом месте (история коммита).
